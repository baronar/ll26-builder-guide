1. Where We Are & The Electrical "Why" Behind What We're Soldering

Physical Tube & Strip Topology (3,600 Total LEDs)

  • 2 Tubes × 2 Opposite Strips: Each 5.0m tube contains two 900-LED WS2812B strips mounted back-to-back (Strip A Forward ▶ LED 0..899 and Strip B Reverse ◀ LED 1799..900).
  • 3-Turn Coiled Hoop Geometry (coilCount = 3): Each 5m tube coils into 3 overlapping 300-LED turns. Firmware projects animations across all 3 turns in lockstep via applyPixelCoiled().
  • Why We Cut DIN at LED 450 (8-Tap Mode = 72.4 FPS): At 800 kHz (30 µs/LED), shifting 900 LEDs takes 27.0 ms (~36.2 FPS). Cutting the copper DIN trace between LED 449 and 450 (while keeping +5V and GND continuous) and feeding LED 450 from a mid-tap pin halves the shift length to 450 LEDs (13.5 ms = 72.4 FPS).
  • Why GND Is Offset by +4 Pads from +5V: Along the strip, every power injection tap solders +5V at Pad N and GND at Pad N+4 (e.g., Pads 6/10, 223/227, 448/452, 673/677, 890/894) so the wires enter the 3D-printed wire_lock channel in staggered slots without overlapping or shorting.

Why the ElectroCookie Shield Uses 6× PN2222A + 2× Direct 330Ω

  • Short Base Lines (D2 → T1-A, D4 → T2-A, <15 cm): Enter the base of the tube right next to the enclosure. Low wire capacitance allows a direct 330 Ω series damping resistor on Column 10.
  • Long Mid-Tap & Far-End Lines (D3, D5, D6, D7, D11, D12, 2.5m–5.0m runs): Running 800 kHz square waves 2.5m to 5.0m up the internal tube channel requires high current drive and source termination. Each channel uses a PN2222A NPN Emitter-Follower:
    1. 100 Ω from Arduino GPIO pin → Base 3-hole bar.
    2. PN2222A Collector (Pin 3) → Center +5V bus; Base (Pin 2) → Base bar; Emitter (Pin 1) → Emitter bar.
    3. 330 Ω pull-down from Emitter bar → Center GND bus (ensures fast fall times for the 12-cycle 0.25 µs T0H bit window).
    4. 22 Ω series output termination from Emitter bar → Output bar → Tube data wire.

2. Program Layout & Codebase Map (v2.545.0)

Embedded Microcontroller Firmware (firmware/)

  • firmware/light_loop_900/light_loop_900.ino & ws2812_parallel.S:
    Main Renesas RA4M1 (48 MHz Cortex-M4F) firmware. Drives 40 procedural & physics modes, the Universal Landing Overlay Compositor (L1–L12), sub-microsecond ARM_DWT_CYCCNT parallel port-register WS2812 output, non-blocking 10–20 Hz sensory bus (VL53L5CX 64-zone ToF LiDAR + HC-SR04 Ultrasonic + DS1307 RTC), and .noinit SRAM crash telemetry.
  • firmware/esp32_unified_bridge/esp32_unified_bridge.ino:
    Dual-Core FreeRTOS firmware for the onboard ESP32-S3 radio co-processor. Core 0 runs an offline Wi-Fi Captive Portal (SSID: LightLoop-Setup, 192.168.4.1) serving the 311.5 KB gzipped React PWA directly from flash ROM with zero internet required. Core 1 runs the Coded PHY BLE GATT peripheral (LightLoop-545) bridged over 115,200-baud Serial2 to the RA4M1.
  • firmware/bench_harness_tester/bench_harness_tester.ino:
    Dedicated bench test sketch for Continuity / Channel / Tap verification during soldering.

React + TypeScript Web & Mobile Suite (Root)

  • index.tsx: Root router (?view=studio, ?view=phone, ?view=checklist, ?view=classic) and 4-phase Web Bluetooth post-connect settling state machine (+550ms, +900ms, +1100ms, +1400ms).
  • LightLoopAdaptiveStudio.tsx: Desktop & tablet studio with concentric 3-coil 60 FPS canvas simulator, 40-mode matrix, 7 live modulators, and 5-zone scrubber.
  • MobilePhoneApp.tsx: Mobile & Google Pixel Fold controller with single-row precision gesture scrubber and Android native BLE Coded PHY bridge support.
  • WiringChecklistApp.tsx: Powers /?view=checklist and checklist.html—syncs soldering progress (64-bit mask) to Arduino Data Flash and fires CHK packets to light individual solder-joint LEDs.
  • LedController.ts: Browser 60 FPS simulation engine mirroring all 40 C++ firmware modes and particle physics 1:1.
  • scripts/: Hardware-in-the-loop CLI tools (read-serial.py, scan-ble.py, test_ble.py, build-firmware.sh).
